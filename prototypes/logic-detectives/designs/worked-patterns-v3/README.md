# Five ways to teach the table rule

These are design mockups, not game changes. The earlier concepts mainly showed
where paths intersected. These explicitly show why the printed numbers are
correct: left9 + top3 = printed12; left9 + top4 = printed13. Missing cells stay
unknown. Each computation restarts with its row's left number; a row is never a
running cumulative sum through the other printed totals.

1. **Equation lens:** click an existing total to link its two headers and show
   one matching colored equation. Lightweight everyday support.
2. **Build one row:** one animation visits successive columns, holding9 fixed.
   Replay the same recipe with different top numbers. Recommended introduction.
3. **Same-start jumps:** two number lines both start at9; three hops reach12,
   four reach13. Concrete meaning for adding.
4. **Same-base bars:** equal blue9 bars gain pink3 or4 extensions; completed
   lengths match printed12 and13. Visual quantities without counting all anew.
5. **Constant and change:** two equations share9; increasing the top number
   from3 to4 increases the sum from12 to13. Grade3 extension. The step is the
   actual difference between the selected headers, not always1.

Blue=start, pink=addend, purple=sum. Known printed examples may be explained
fully; a hidden answer or hidden header must not be generated by these views.
All calculations in the pictures are exact. Regenerate with
`draw-five-concepts.ps1`, using the local Windows drawing API.
